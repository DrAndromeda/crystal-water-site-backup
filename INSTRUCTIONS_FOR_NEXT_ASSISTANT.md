## Известные баги — исправить

### 1. 🔴 sitemap.xml — сломанные URL (КРИТИЧНО)
В файле `sitemap.xml` у 7 записей отсутствует `/` после домена:
```
БЫЛО:  https://crystalwater.kiev.uaabout.html
НАДО:  https://crystalwater.kiev.ua/about.html
```
Затронутые файлы: about.html, articles.html, o-nas.html, prices.html, tech.html,
tekhnologii-ochistki.html, uslugi-i-tseny.html
→ Найди в генераторе sitemap место, где склеивается `base_url + filename` без
разделителя, почини сам генератор, не только вывод.

### 2. 🟡 Битые ссылки на логотип и "Доставка воды" в хедере
Сейчас `href="/"` — на GitHub Pages (project page) это резолвится в корень
аккаунта (`drandromeda.github.io/`), а не сайта. На боевом домене будет
работать нормально, но для тестирования на стейджинге замени на
относительный путь `href="./"`.

### 3. 🟡 Несовпадение ссылки на UA-версию
В хедере было: `ua.html` (один файл)
В футере было: `/ua/` (папка)
**Решено пользователем: правильная структура — папка `/ua/` с отдельными
страницами**, зеркалящими RU 1:1 по slug. Убрать все ссылки на `ua.html`,
везде использовать `/ua/`. На внутренних страницах ссылка UA должна вести
на соответствующую UA-версию ИМЕННО этой страницы
(`/prices.html` → `/ua/prices.html`), не всегда на корень `/ua/`.

### 4. 🟡 og:image — относительные пути вместо абсолютных
На некоторых страницах (например prices.html) og:image указан относительным
путём (`images/bottle_articles.png`). Соцсети/мессенджеры не резолвят
относительные пути в OG-тегах — превью будет пустым. Нужны абсолютные URL
везде: `https://crystalwater.kiev.ua/images/...`

### 5. 🟢 Разнобой соцсетей в футере на разных страницах
Проверить все 71 страницу — на некоторых были разные аккаунты
(crystalwater.brovary vs crystalwater.kiev.ua vs twitter @CrystalWoter).
Свести к единому набору ссылок глобально (используй тот, что в футере
главной страницы, он выглядит финальным).

### 6. Опечатка
prices.html: "оплачивается залоговая стоимость **за бутыля**" →
"за бутыль"

### 7. Артефакт markdown-конвертации
prices.html: строка вида `**** При первой доставке ... *` — проверить,
не остались ли сырые `**`/`*` вместо `<strong>` или сноски в реальном HTML.

## Порядок выполнения (рекомендованный)

1. `git commit` текущего состояния (точка отката)
2. `python3 fix_site_issues.py` — чинит sitemap.xml, canonical/og:url
   на github.io, относительные og:image, опечатку "за бутыля"
3. `python3 add_hreflang.py` — добавляет hreflang-пары на все RU/UA
   страницы автоматически (не нужно делать 142 правки вручную)
3.5. `python3 generate_sitemap_ua.py` — создаёт sitemap-ua.xml на основе
   существующего sitemap.xml (проверь, что он ещё не создан вручную —
   скрипт не перезапишет без --force)
3.6. `python3 unify_social_links.py` — ⚠️ ПЕРЕД запуском сверь с
   пользователем, какие соцсети актуальные (см. комментарий в начале
   скрипта) — он по умолчанию убирает twitter-ссылку полностью и
   унифицирует instagram/facebook на аккаунты crystalwater.brovary
4. `bash apply-css.sh` — подключает CSS ко всем страницам
5. Вручную вставить разметку из `header-footer.html` вместо старого
   хедера/футера
6. Вставить JSON-LD: `json-ld-index.html` (главная), `json-ld-prices.html`
   (страница цен), `json-ld-about.html` (о нас/контакты) — вручную,
   это всего 3 страницы. ⚠️ В `json-ld-prices.html` цены Product взяты
   со скриншота, который прислал пользователь — сверь актуальность
   перед публикацией.
   Для статей (60+ страниц) — запусти `python3 generate_article_jsonld.py`,
   он автоматически вытащит title/h1 с каждой страницы и вставит Article +
   BreadcrumbList JSON-LD. ⚠️ Даты publish/modified в нём — заглушка
   (дата запуска скрипта), замени на реальные, если найдёшь в архивах.
7. Применить переписанные тексты из `medical-claims-rewrite.md`
8. Проверить чек-лист `images-mobile-performance-checklist.md`
9. git diff, показать пользователю, затем commit + push
