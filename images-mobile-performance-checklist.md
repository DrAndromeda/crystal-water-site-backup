# Чек-листы для проверки перед деплоем — пункты 11, 12, 13 ТЗ

## Пункт 11 — Изображения

Для КАЖДОГО изображения на сайте проверить:

- [ ] Формат WebP (или AVIF), а не JPEG/PNG — конвертировать существующие
      `cwebp -q 80 input.jpg -o output.webp`
- [ ] Указаны атрибуты `width` и `height` в теге `<img>` — это резервирует
      место на странице и напрямую снижает CLS (пункт 13)
- [ ] `alt` заполнен осмысленным текстом на русском/украинском
      (НЕ "image1.png", а например "Бутыль питьевой воды Crystal Water 19 литров")
- [ ] Изображение отдаётся в размере, соответствующем фактическому
      отображению — если на странице картинка 300px шириной, не грузить
      исходник 3000px
- [ ] `loading="lazy"` на всех изображениях НИЖЕ первого экрана
      (первый экран / hero — БЕЗ lazy, чтобы не тормозить LCP)

Пример правильного тега:
```html
<img src="/images/bottle-19l.webp"
     alt="Бутыль питьевой воды Crystal Water 19 литров"
     width="400" height="600"
     loading="lazy">
```

Для hero-изображения (первый экран):
```html
<img src="/images/hero-bottle.webp"
     alt="Доставка воды Crystal Water в Броварах"
     width="600" height="800">
<!-- без loading="lazy" — это часть LCP -->
```

## Пункт 12 — Мобильное тестирование

Проверить КАЖДУЮ страницу на следующих ширинах (через DevTools →
Responsive mode, точные значения viewport):

| Устройство         | Ширина  |
|---------------------|---------|
| iPhone SE            | 375px   |
| iPhone 13/14/15       | 390px   |
| iPhone Pro Max        | 430px   |
| Android (малый)       | 360px   |
| Android (средний)     | 390px   |
| Tablet (портрет)      | 768px   |
| Desktop                | 1280px+ |

На каждой ширине проверить:
- [ ] Нет горизонтального скролла (`overflow-x: hidden` на body — как
      подстраховка, но лучше найти и исправить первопричину переполнения)
- [ ] Футер не разваливается, все колонки читаемы
- [ ] Меню открывается/закрывается корректно (у нас — статичное, без
      скрытия, но всё равно проверить перенос строк)
- [ ] Кнопки не обрезаны и не наезжают друг на друга
- [ ] Sticky mobile order bar снизу не перекрывает последний блок
      контента (проверить `padding-bottom` на body)
- [ ] Текст не вылезает за карточки/контейнеры

Быстрая diagnostic-команда в консоли браузера для поиска элементов,
вызывающих горизонтальный overflow:
```js
[...document.querySelectorAll('*')].forEach(el => {
  if (el.scrollWidth > document.documentElement.clientWidth) {
    console.log(el);
  }
});
```

## Пункт 13 — Производительность (Core Web Vitals)

Цели:
- LCP (Largest Contentful Paint) < 2.5 сек
- INP (Interaction to Next Paint) < 200 мс
- CLS (Cumulative Layout Shift) < 0.1

Как проверить: https://pagespeed.web.dev/ — вставить URL страницы,
проверить и Mobile, и Desktop отдельно.

Быстрые точки влияния:
- LCP чаще всего = главное изображение или h1 — убедиться, что hero-картинка
  оптимизирована (см. пункт 11) и без lazy-loading
- CLS чаще всего = картинки без width/height, или веб-шрифты без
  `font-display: swap`, или динамически подгружаемые баннеры/виджеты
  без зарезервированного места
- INP чаще всего = тяжёлые обработчики кликов/скролла в JS — если
  добавляли скрипты (аналитика, чат-виджеты), проверить, не блокируют
  ли они основной поток

Проверить на реальных страницах: главная, prices.html, одна статья
(самая тяжёлая по картинкам) — не ограничиваться только главной.
